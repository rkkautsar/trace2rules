# trace2rules

Mine coding-agent sessions into evidence-backed `AGENTS.md` rules.

`trace2rules` is a local-first CLI. It ingests agent trajectories, detects recurring friction (setup failures, repeated exceptions, oversized output, rediscovery hotspots), and proposes a small number of repository-specific rules with the evidence attached.

Status: alpha. The output is a proposal, not an automatically applied `AGENTS.md`.

## Example finding

On the demo corpus, [PDM](https://github.com/pdm-project/pdm), a Python package manager, showed its most expensive repeated friction as a setup loop: `import pdm` failed until `pip install -e .` was run. It appeared in 39 sessions and accounted for ~95,576 setup tokens.

`synthesize` turns that into:

```markdown
# AGENTS.proposed.md

Generated by trace2rules from 200 sessions in pdm-project/pdm.

## test_command
- **Rule:** Run `pip install -e .` before import, CLI, or pytest probes.
  **Evidence:** 39 sessions; 95,576 setup tokens.
```

Rules are capped at 5 rules, 60 lines, and 2,500 characters per repo.

## Supported inputs

| Format | What it reads | Notes |
|---|---|---|
| `swe-rebench` | `nebius/SWE-rebench-openhands-trajectories` parquet | Default; streamed from Hugging Face |
| `swe-chat` | `SALT-NLP/SWE-chat` parquet tables | Normalized `sessions.parquet` + `conversations.parquet`; gated dataset |
| `agent-trajectory` | Local Claude Code, Codex, Pi, OMP, and OpenCode exports | Uses [`agent-trajectory`](https://github.com/letta-ai/trajectory); requires Node.js 20+ |

Datasets are not included in this repository.

## Install

Base install (SWE-rebench and SWE-chat):

```bash
uv sync
```

Local-session support:

```bash
uv sync --extra local
# or
pip install -e '.[local]'
```

`agent-trajectory` shells out to a bundled Node runtime. Install Node.js 20 or newer before using `--format agent-trajectory`.

## Quick start

```bash
uv run trace2rules ingest --repos django__django --limit 50
uv run trace2rules mine
uv run trace2rules synthesize --offline
```

`ingest` writes to `data/trace2rules.duckdb` by default. `mine`, `exact`, and `synthesize` read from it.

### SWE-chat

Request access on the [dataset page](https://huggingface.co/datasets/SALT-NLP/SWE-chat), then download the two tables:

```bash
hf download SALT-NLP/SWE-chat \
  --repo-type dataset \
  --include "sessions.parquet" \
  --include "conversations.parquet" \
  --local-dir data/swe-chat

uv run trace2rules ingest \
  --format swe-chat \
  --source data/swe-chat \
  --limit 0

uv run trace2rules mine
uv run trace2rules synthesize --offline
```

`--limit 0` imports the full corpus. The default limit is 200 sessions.

### Local agent sessions

```bash
uv run trace2rules ingest \
  --format agent-trajectory \
  --source ~ \
  --limit 0
```

With `--source ~`, it scans the standard stores:

- `~/.claude/projects`
- `~/.codex/sessions`
- `~/.pi/agent/sessions`
- `~/.omp/agent/sessions`

Pass a specific directory to limit the scan. OpenCode stores sessions in SQLite; export first:

```bash
opencode export <session-id> > session.json
uv run trace2rules ingest --format agent-trajectory --source session.json
```

Use `--repo owner/name` to override the repository label for local sessions.

## Commands

| Command | Purpose |
|---|---|
| `ingest` | Load sessions and tool events into DuckDB |
| `mine` | Show friction clusters, hotspots, recovery loops, and context blasts |
| `label` | Label normalized targets through the configured Cloudflare backend |
| `patterns` | Mine multi-step sequence patterns |
| `exact` | Show exact recurring sequences with evidence |
| `synthesize` | Write per-repo `.proposed.md` files |

Useful options:

```bash
trace2rules ingest --format swe-rebench|swe-chat|agent-trajectory
trace2rules ingest --source PATH --limit 200
trace2rules synthesize --offline
trace2rules synthesize --repo owner/name --out AGENTS.proposed.md
trace2rules synthesize --repo owner/name --out -
trace2rules synthesize --out-dir ./proposals
```

`--out -` writes the markdown to stdout and sends progress/findings to stderr.

`--offline` skips the LLM and uses deterministic rules. Without `--offline`, synthesis uses an OpenAI-compatible endpoint.

## Configuration

| Variable | Purpose |
|---|---|
| `GEMINI_API_KEY` | Gemini synthesis provider |
| `OPENAI_API_KEY` | OpenAI synthesis provider |
| `TRACE2RULES_API_KEY` | Explicit synthesis API key |
| `TRACE2RULES_BASE_URL` | OpenAI-compatible base URL (including LiteLLM) |
| `TRACE2RULES_MODEL` | Synthesis model, e.g. `gemini-4-hydrogen` |
| `HF_TOKEN` | Gated Hugging Face dataset access |

`TRACE2RULES_BASE_URL` also works with an OpenAI-compatible LiteLLM proxy.

## How it works

1. **Ingest** normalizes tool calls into DuckDB (`sessions`, `tool_events`).
2. **Detectors** find high-coverage setup failures, repeated exception signatures, read-only hotspots, and large output calls.
3. **Exact sequence mining** groups recurring 3-step tool sequences with lift and paired-rework evidence.
4. **Synthesis** selects gated findings and writes one proposal per repo, via an LLM or deterministically with `--offline`.

Generated verifier scripts and low-support task-specific sequences are filtered before synthesis.

## Data and privacy

- Session data stays in your local DuckDB database.
- `--offline` performs no LLM calls.
- LLM synthesis sends mined findings, not the full raw session database. Findings can still contain commands, paths, and repository names; review before using an external provider.
- `label` uses an external backend and should not be used on sensitive private sessions without review.
- `data/` and generated `AGENTS.*.proposed.md` files are gitignored.

## Known limits

- Detectors are heuristics. Review every proposed rule.
- SWE-chat has no `resolved` field; `session_success` (0–100) is stored separately as `success_score`.
- SWE-chat tool results are truncated to 10 KB and do not carry an explicit error flag; outcomes are inferred from text and exit codes.
- Local-session formats change frequently. `agent-trajectory` is the compatibility layer; pin its version.
- Full SWE-chat import and synthesis were not part of the release smoke test.
